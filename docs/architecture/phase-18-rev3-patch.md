**`SafeFs` (owned by 18E, additive).** Five new exports:

- `readBoundedPrivateJson(file, { maxBytes, maxDepth, root, requireMode, requireOwner, parse })` — as rev 2, plus: the check is `(st.mode & 0o077) === 0` **in addition to** the exact `requireMode` comparison, so a group- or world-readable/writable file is refused `READ_MODE_UNSAFE` even if a future caller omits `requireMode`. `win32` is refused as in rev 2.
- `writeAtomicPrivateSynced(file, content)` — unchanged.
- `createExclusive(file, content)` — `open(file,"wx",0o600)`, write, `fh.sync()`, close, directory `fsync`. `EEXIST` → `{ok:false, code:"EXISTS"}`. **C3: a zero-length existing file counts as `EXISTS` (consumed), never as absent or as a resumable partial** — the caller must not retry, must not truncate and must not treat `size === 0` as "not yet written"; `createExclusive` therefore never opens with `O_TRUNC` and `ApprovalStore` treats any existing marker, including a 0-byte one, as consumption (the SIGKILL-between-open-and-write window is biased to "lost", which is the correct bias, P02).
- `lockExclusive(lockPath, { timeoutMs = 5000, staleMs = 60000 })` — **D-1**. Creates `lockPath` with `open(...,"wx",0o600)` containing `{pid, startedAtIso, hostname, bootIdOrMonotonic}` + `fh.sync()` + directory `fsync`. On `EEXIST` it reads the holder record through `readBoundedPrivateJson`: if `process.kill(pid,0)` throws `ESRCH` **and** the record is older than `staleMs`, the lock is stale and is broken by `rename`-ing it to `lockPath + ".stale." + random` (never `unlink`, so a racing holder cannot have its live lock silently removed) and retrying once; `EPERM` from `process.kill` means a live foreign-uid process and is **not** stale (refuse). Otherwise it retries with jittered backoff until `timeoutMs`, then returns `{ok:false, code:"LOCK_TIMEOUT"}`. `unlock(handle)` verifies the on-disk record still names this pid before unlinking (re-`lstat` + content compare), so a process that lost a stale-break race never deletes somebody else's lock. Reentrancy is in-process: an async-local depth counter makes nested acquisition by the same run a no-op, which is why there is also no in-process deadlock between `consume` and the audit append.
- `assertLocalFilesystem(dir)` — **N-5, C3.** `fs.statfs(dir)` and an **allowlist** of filesystem types, refusing everything else (so virtiofs, FUSE, drvfs, NFS, SMB, overlay and anything unrecognised are refused, rather than enumerating the bad ones): `linux` → `ext4 (0xEF53)`, `xfs (0x58465342)`, `btrfs (0x9123683E)`; `darwin` → `apfs`, `hfs`. Failure is `PILOT_INTERNAL_ERROR` (exit 18) naming the observed numeric/string type and the path, with no override flag or env var. Applied to `PilotRoots.approvalsRoot` (atomic `O_EXCL` and `fsync` semantics are load-bearing there), to `authRoot` and to `plansRoot`, once at `PilotLifecycle` start. **OWNER DECISION (OD-20):** whether to extend the allowlist to `tmpfs`/`zfs`/`ext2`/`ext3` for CI runners; until the owner decides, the list above is the design and CI must run on one of these types.

**`PilotRoots` (fixed, not operator-configurable).** As rev 2, plus **F01 addition:** `repoRoot` is computed **once at module load** as `fs.realpathSync(path.join(__dirname,"..","..",".."))` and is frozen; the `package.json` name check runs against the realpath. Every later confinement comparison (`resolveUnder`, parent-component `lstat`, `Retention` candidates) is made against this realpath, so a symlinked checkout, a `/var`→`/private/var` style prefix (macOS) or a parent component replaced after startup cannot produce a path that passes `resolveUnder` but resolves outside the root. A realpath failure, a name mismatch, or a `repoRoot` that is not a directory owned by the process uid is `PILOT_INTERNAL_ERROR`. Negative test: `neg-f01-realpath` (U) — a symlinked repo root and a `..`-containing `__dirname` both resolve to the same frozen realpath, and a path under a symlinked sibling is refused.

  **L08-vs-P04 resolution (SEC-03 asks the architect to pick one). Decision: keep L08's fail-closed refusal, and scope it to runs that actually touch a state file.** The ignore check is required only where a session file could be committed, i.e. when a manifest role declares `stateFile` or when `--save-state`/`--auth-import` is used. 3. **Method gate, both directions (N01).** In execute mode **every** request whose method is not `GET` or `HEAD` is aborted unless the gate is armed and the request's `{method, serialised origin, canonical path}` equals the armed triple exactly; arming is consumed by the first matching request. **New in rev 3 — denied-route GETs and navigations are also aborted in execute mode, not only in dry-run:** any request (any method, including `GET`/`HEAD`, including a document navigation and including a redirect hop) whose canonical path is `denied` by `RouteMatch.decide` for its method, or whose origin is not allow-listed for its resource type, is aborted and counted as `POLICY_NETWORK_BLOCKED` / `POLICY_ROUTE_DENIED`. This closes the N01 gap: a page script doing `location = "/account/delete?confirm=1"`, a `<a href>` to a destructive GET route, a `<meta refresh>`, a `window.open`, and a 302 whose `Location` names a denied route are all stopped at the network layer, independently of the classifier and independently of whether an element was clicked. `RouteMatch.decide` is evaluated per request with the request's own method, so a route denied only for `POST` still permits its `GET`, and a route denied outright denies both. Negative test: `neg-n01-exec-denied-get` — in execute mode, a permitted click whose handler sets `location` to a denied GET route, a redirect into a denied route, and a `<meta refresh>` into one: each aborted, `POLICY_NETWORK_BLOCKED`, fixture mutation counter 0, zero navigations recorded by the fixture for that path.
4. **`sendBeacon`, preflight, WebSocket, workers.**
   - Beacons are `POST`s, covered by (3).
   - **OPTIONS preflight (N-3).** A CORS preflight is an `OPTIONS` request the browser issues itself, so rule (3) would abort it and break an otherwise approved cross-origin POST. The lease therefore carries `preflightAllowed: true`: while a lease for `{POST|PUT|PATCH|DELETE, origin, path}` is open, **exactly one** `OPTIONS` to the same `{origin, path}` is permitted and sets `preflightAllowed = false`; it does not consume the lease. For an allow-listed origin the handler connects and then drops **every** outbound frame (Phase 18 never arms a WebSocket action), forwards inbound frames to the page, and counts drops. 5. **Redirect cap and per-hop validation (N-3).** At most `MAX_REDIRECTS = 10` hops; exceeding it is `POLICY_REDIRECT_LIMIT`. Per-hop origin/route validation is the declared spike **SPIKE-R**; hypothesis H-R (a `route` handler may not fire for every hop) is **not verified and is not claimed either way**. If the spike shows each hop is observed, validation happens in the handler. **Mandated fallback otherwise (the default implementation unless the spike proves the simpler path):** every intercepted request in a pilot context is dispatched with `route.fetch(request, { maxRedirects: 0 })` in a Falcon-side loop that, for each hop, validates the `Location` target against item 2 (scheme/userinfo), item 3 (method, origin, canonical route, armed triple) and the hop cap, and aborts on the first denied hop. Two properties the fallback **must** have, both of which the spike must confirm before 18C merges:
   - **The browser must re-request each hop; Falcon must never follow a redirect server-side.** When a hop is permitted, the handler calls `route.fulfill()` with the 3xx status, headers (including `Location` and any `Set-Cookie`) and empty body, and lets the browser issue the next request itself. Following hops inside Falcon and fulfilling the page with the *final* body would render origin B's content under origin A's origin — a same-origin-policy break worse than the redirect it was trying to police — and would also hide the intermediate `Set-Cookie`s from the cookie jar. Only the terminal non-3xx response is fulfilled with its body.
   - **`route.fetch` must send exactly the cookies and headers the browser would have sent.** This is an assumption about Playwright, not a fact this design asserts: the spike must verify, against the fixture, that the cookie jar, `Referer`, `Origin`, `Sec-Fetch-*` and custom headers of the intercepted request are reproduced, and that `Set-Cookie` on the fulfilled response reaches the context's jar. If any of these does not hold, 18C may **not** ship the fallback as a transparent proxy; the fallback then degrades to refusing the redirect (`POLICY_REDIRECT_LIMIT` with reason `hop_unverifiable`, exit 13) and the limitation is documented. Negative tests: `spike-r-redirect-hops` (records the observed behaviour and which branch shipped), plus `neg-n01-network`'s 302 case, which must pass through whichever branch shipped, and a new `neg-n01-redirect-cookie` asserting the fixture sees the session cookie on every hop and that a hop into a denied route is aborted.
7. **No cross-origin content substitution.** A `fulfill` in a pilot context may only carry (a) the upstream response for the *same* request URL, or (b) an abort. There is no path that serves bytes fetched from one origin as a response for another; asserted by a unit test over the route handler.
8. **Arming window (N-2, P03).** See section 9 "Arming window".
9. **Fail closed.** Any throw inside a route handler aborts the request and refuses the run with `PILOT_INTERNAL_ERROR`.

### 7b. Playwright-runner artifacts: a separate `playwright.pilot.config.js` (L03)

A project-level override inside `playwright.config.js` cannot work, for three reasons verified in that file: reporters are declared at the **top level** (`json` → `reports/playwright-results.json` and `allure-playwright`), so a pilot project still persists error call logs and attachments to `reports/` and `allure-results/`, outside the boundary; the top-level `testIgnore: ["**/regression/**","**/demo/**"]` excludes `tests/regression/pilot/**` before any project `testMatch` applies; and `baseURL` falls through to `https://www.saucedemo.com`, a third-party site. **Decision: 18F adds a separate `playwright.pilot.config.js`, following the `playwright.demo.config.js` precedent, and the `pilot` project is removed from `playwright.config.js` entirely.**

```js
// playwright.pilot.config.js  (owned by 18F)
module.exports = defineConfig({
  testDir: "./tests/regression/pilot",
  testMatch: "**/*.test.js",
  testIgnore: [],                       // nothing inherited; the pilot dir IS the suite
  retries: 0,
  workers: 1,
  fullyParallel: false,
  reporter: [["list"], ["json", { outputFile: "run/pilot-test-results/results.json" }]],
  // No allure reporter: allure-results/ is outside PilotRoots, is not retention-governed
  // and attaches failure context verbatim.
  use: {
    baseURL: undefined,                 // the hermetic fixture supplies absolute URLs
    screenshot: "off", video: "off", trace: "off",
    contextOptions: { recordVideo: undefined, recordHar: undefined },
    serviceWorkers: "block", acceptDownloads: false, strictSelectors: true,
  },
  outputDir: "run/pilot-test-results/",
  projects: [{ name: "pilot", use: { ...devices["Desktop Chrome"] } }],
});
```

Invariants: the pilot config ignores `BASE_URL` and `HEADLESS=false` is permitted but `DEBUG` is not (section 10); `outputDir` is inside `PilotRoots`-governed `run/`, which C8 git-ignores and section 17 retention cleans; the json reporter output is inside the boundary root and is scanned by the canary suite; `npm run test:pilot` is `playwright test --config=playwright.pilot.config.js` and the CI pilot job uses only that config. `VisualRegression` still consults `manifest.artifacts` and refuses to capture when `screenshots === "none"` or when the role is authenticated and the route is not in `screenshotRoutes`.

Negative test `neg-l03-runner-artifacts` (replacing rev 2's): a forced failure in the pilot config produces zero `*.png`, `*.webm`, `*.zip`, `*.har` and zero new files under **all four** locations — `run/pilot-test-results/` (the real outputDir), `reports/` (including `reports/test-artifacts/` and `reports/playwright-results.json`), `allure-results/`, and `test-results/` (asserted absent, since nothing should create Playwright's default dir) — plus an assertion that the pilot suite is actually collected (a deliberately failing placeholder test must fail, proving `testIgnore` does not swallow the suite) and that `traces: "trace-on"` for an authenticated role is `MANIFEST_INVALID`. **`falconBuild` (P04, C2, ADR-0034). `BuildIdentity` does not reuse `GitInfo`.** `src/core/history/GitInfo.js:38` prefers `env.GITHUB_SHA` and has no dirty flag, so an attacker or a misconfigured CI step that sets `GITHUB_SHA` could make an approval granted for build A appear valid for build B. `BuildIdentity.falconBuild()` therefore:

**Barriers and flush semantics (L01).** `Logger`'s console emission is synchronous but its file append is queued on `Logger._writeQueue` and drained only by `await Logger.flush()` (`utils/Logger.js:108,134,155`), while the cookie/storage diff is `async`. Registering inside the diff therefore cannot be relied on to precede a synchronous `console` write. Resolution has two parts, so no sink can ever outrun a registration:

1. **Asynchronous sinks await `boundary.settle()`.** `settle()` awaits the in-flight cookie/storage diff (and any pending JSON-body parse) and resolves only when the registry is current. Every async sink — report writes, plan file, audit chain, shard bundle, run history, locator memory, healing evidence, dashboard emit, screenshot metadata, provider prompt — calls `await EvidenceBoundary.settle(boundary)` as its **first** statement, before sanitisation. A `settle()` rejection or timeout (2 s) is `PILOT_INTERNAL_ERROR` and nothing is written (E01).
2. **Synchronous sinks cannot carry free text at all.** In pilot mode `Logger.info/warning/error`, `process.stdout.write` and `process.stderr.write` on pilot paths accept only `EvidenceBoundary.logCoded(boundary, { code, fields })`, where `code ∈ FailureCodes.CODES` and `fields` is restricted to an allow-list of non-secret shapes (`route`, `role`, `actionId`, `classification`, `counters`, `seq`, `segmentId`, `exitCode`, bounded integers and enum strings) — never a response body, a header, a cookie, a storage value or an exception message. Free text (including error messages) is only ever written through the async sinks that have settled. Consequently the async-diff-versus-sync-console race is **structurally** absent rather than mitigated: a value that is not yet registered also cannot reach the only channel that could not wait for it. `PilotLifecycle.cleanupAll` ends with `await Logger.flush()` after a final `settle()`, so the queued appends are on disk before exit, and the exit-code paths call cleanup explicitly (section 17, F03).

**Barrier points** (where the diff runs): after every navigation commit and `load`, after every `gate.perform` (before `settleLease` returns), on every `response` with a `Set-Cookie`, before every async sink write (via `settle`), and at run end.

**Worker registries and shard merge (L01).** Each worker has its own boundary, so values discovered in worker 3 are unknown to the coordinator that merges bundles. Two layers, in this order of reliance:

1. **Worker-local `assertClean` at write time is the control.** A worker's bundle is written through its own boundary with its own complete registry, so anything it wrote was already asserted clean against the values it knew. `ShardMerge` **refuses** a bundle that lacks a `boundaryAttestation { registrySize, derivedForms, assertCleanCount, settleCount, mode }`, or whose attestation reports `assertCleanCount === 0`, or whose mode disagrees with the run mode (`PILOT_INTERNAL_ERROR`, bundle not merged) — a worker that bypassed the boundary cannot be merged.
2. **Union by blinded index, for the coordinator's own re-scan.** Registered values must never travel in a bundle. The coordinator mints a 256-bit per-run `registryKey` in memory and passes it to each worker in the spawn environment (never to disk, never to a log, registered as a secret itself); each worker publishes `secretIndex = [HMAC-SHA256(registryKey, form)]` over all derived forms of all its registered values, in sorted order. At merge the coordinator unions every bundle's `secretIndex` with its own, then re-scans the merged artifacts by extracting candidate tokens (maximal runs of `[A-Za-z0-9+/=_%.~-]{8,}`, plus their single and double percent-decodings, base64/base64url decodings and JSON-unescaped forms), HMAC-ing each candidate and looking it up in the union. A hit refuses the merge with `EVIDENCE_LEAK_DETECTED` and writes nothing. Cost is linear in merged bytes with a bounded candidate set. **Residual, documented:** a value embedded without token boundaries (for example inside a longer unbroken string) is not found by candidate extraction at merge time; layer 1 is what covers it, and the canary suite's shard run shape is the test. The run token is deliberately **not** in any `secretIndex` (workers never receive it).

**Literal matching only (C4, S02).** `SecretRegistry` substitution and `assertClean` use **literal** matching — `indexOf`/`lastIndexOf` scanning with a longest-match-first ordered table, or an Aho-Corasick automaton built once per registry version — and **never** construct a `RegExp` from a registered value. A secret containing regex metacharacters would otherwise either mis-match or create a catastrophic-backtracking input (S02). The fixed `Schemas.SECRET_PATTERNS` and `Logger.redactUrlUserinfo` patterns stay, are anchored, have no nested quantifiers, and are applied to inputs capped at 1 MiB. Negative test: `neg-s02-redos` (U) — a 1 MiB adversarial string with a registry of 512 values, including values made entirely of metacharacters (`.*+?[](){}|\^$`), is processed in under 100 ms and the metacharacter values are still redacted; a unit test asserts the registry module contains no `new RegExp` over registered input.

**Pre-existing directories and files (F02, corrected).** At startup `run/`, `run/plans/`, `run/pilot-test-results/` and `reports/execution.log` are verified or **repaired** (`chmod` only when the owner is the process uid, refuse otherwise), as rev 2. **Retention (AC-068, OD-14, C6).** As rev 2 (7 days for artifacts, 90 days for sealed segment bodies, `anchors.log` never pruned, 120 days for consume markers per section 9), plus **C6: immediately before each `unlink` or `rmdir`, every parent component of the candidate — from `PilotRoots.repoRoot`'s realpath down — is re-`lstat`-ed and compared with the `lstat` taken when the candidate was enumerated (device, inode, mode, uid, type).** A mismatch, a symlink, or a non-directory aborts that deletion, reports it, and continues with the next candidate; it never deletes through the new path. This closes the parent-swap race where an attacker replaces a directory between enumeration and unlink. Deletions are additionally performed with `unlinkat`-equivalent semantics where available by opening the parent directory once and operating relative to that fd, so even a successful swap after the check cannot redirect the unlink. Candidate enumeration itself remains `lstat`-only, `resolveUnder`-confined and bounded. ### ADR-0027 (amended, C1/N-4) — strict `Digest` with JCS semantics, domain separation and a closed domain list.
Amended: `DOMAINS` is `{plan-v1, manifest-v1, approval-v1, action-v1, state-v1, audit-v1, build-v1, runtoken-v1}` and `digest()` **rejects an unknown or inherited domain** (`DIGEST_DOMAIN_UNKNOWN`) rather than hashing an arbitrary label, so a future caller cannot invent a namespace that collides. `canonicalise` additionally rejects **sparse arrays** (`Object.keys(arr).length !== arr.length`, so `[1,,3]` is refused rather than hashing a hole as `null`), **accessor properties** (any own descriptor with `get`/`set`, which would otherwise be invoked during serialisation), and **symbol-keyed properties** (`Object.getOwnPropertySymbols(obj).length > 0`), and applies the **NFC and lone-surrogate checks to keys as well as values**. `digestIdentity` NFC-normalises page- and filesystem-derived strings and keys before canonicalising and is permitted only for `action-v1`, `state-v1` and `build-v1` (N-4); authored material keeps the rejection. Golden vectors are required for **every** added rule: unknown domain, each new domain, sparse array, getter, setter, symbol key, non-NFC key, escaped lone surrogate in a key and in a value, plus the rev 2 vectors; and a cross-domain collision attempt for each new domain pair. Status: accepted (amended).

### ADR-0030 (amended, F01/F02/N-5/C3/C5) — fixed pilot roots and a privileged `SafeFs` loader.
Amended: `repoRoot` is a frozen `realpathSync` computed once at module load and is the basis of every confinement comparison; the loader refuses any `mode & 0o077` in addition to the exact `requireMode`; `run/approvals` and `run/auth` with any group or world bit are **refused, not repaired**; filesystem type is checked against an **allowlist** (`ext4`/`xfs`/`btrfs` on Linux, `apfs`/`hfs` on macOS) with everything else — NFS, SMB, FUSE, virtiofs, drvfs, overlay, unknown — refused, so the `O_EXCL`/`fsync` assumptions are never silently unmet; `createExclusive` treats a zero-length existing marker as `EXISTS`. Consequences: some developer and CI environments (containers on overlayfs, WSL `drvfs`, dev containers on virtiofs) cannot run pilot mode until the owner extends the allowlist (OD-20); this is a deliberate fail-closed cost. Status: accepted (amended).

### ADR-0032 (amended, D-2/D-3/D-5/D-6) — run scope is a minted batch token, claimed once by the coordinator, transported out of band.
Amended: one `{runId, nonce}` covers a **batch** of approved `actionId`s (D-3) so a plan with several protected actions is runnable; the record stores `nonceHash` as well as `runIdHash` so the nonce is verifiable (D-2); the **coordinator** claims `runtokens/used/<runId>` once before spawning workers, and workers present only `runId` plus a claim receipt (D-3); the `--approval-run-token=` flag is **removed** in favour of `PILOT_APPROVAL_RUN_TOKEN` or a `0600` file, and `rejectKeyCarrierFlags` is extended to reject token-shaped argv (D-5); the token is emitted exactly once through `RunTokenEmitter.emitOnce`, the single documented boundary-exempt channel, allow-listed by the sink scan (D-5, C7), and is **not** added to `.env.example`; CI masks it with `::add-mask::` before any other step action; `--approve-action` refuses a digest with no recorded review (D-6). Status: accepted (amended).

### ADR-0033 (amended, S01/D-4) — audit segments with a never-pruned anchor chain.
Amended: segments seal at 4096 entries, 30 days **or ~768 KiB**, whichever first, so a segment can never exceed the 1 MiB ledger cap; `anchors.log` is **appended** under the ledger lock, never rewritten; `verify()` enforces the five rules in section 9 (anchor chain intact and present; body or `segment-pruned` for every anchor; body **required** for any sealed segment younger than 90 days; globally contiguous `seq`; every marker backed by a `consume-intent` entry), and marker retention is 120 days — between the 1800 s TTL and the 90-day segment retention — so deleting a segment is never indistinguishable from pruning one. Status: accepted (amended).

### ADR-0034 (amended, P04/C2) — `falconBuild` is determinate and independent of `GitInfo`.
Amended: `BuildIdentity` does **not** import `src/core/history/GitInfo` (which prefers `GITHUB_SHA` and has no dirty flag); it ignores `GITHUB_SHA`, strips `GIT_*`/`HOME`/`XDG_CONFIG_HOME` and pins `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` to `/dev/null`; dirtiness is `git status --porcelain --untracked-files=all`; the source fallback uses its own domain `build-v1` over an extended fixed file list that now includes `falcon.js`, `BrowserManager.js`, `Runner.js`, `TestRunner.js`, `ReportManager.js`, `SiteSweep.js`, `ParallelDiscovery.js`, `ShardBundle.js`, `HealingBenchmark.js`, `ElementFactsCollector.js`, `package-lock.json` and `playwright.pilot.config.js`; the fallback is reachable because the L08 ignore check is scoped to runs that touch a state file (section 4). Status: accepted (amended).

### ADR-0035 (new) — Every ledger write holds an `O_EXCL` lockfile with stale-PID detection.
Context: ADR-0031 supports concurrent consumers (AC-021, AC-051 need worker-mode parity), but rev 2 had no cross-process or in-process lock for appending to the chain: two consumers read the same head, append two entries with the same `prevHash`, fork the chain, and every later `verify()` fails `APPROVAL_HISTORY_TAMPERED` — a self-inflicted permanent denial of service — while the `anchors.log` whole-file rewrite was last-writer-wins. Decision: `run/approvals/.ledger.lock` via `SafeFs.lockExclusive` (`open(...,"wx",0600)` + `fsync`, holder record with pid/start time, dead-PID **and** age for staleness, rename-aside rather than unlink, 5 s timeout, in-process reentrancy counter) wraps every segment append, seal, anchor append and `approvals.json` rewrite; the chain head is re-read after acquiring; `anchors.log` is append-only; `LOCK_TIMEOUT` is exit 18 with zero clicks and no lock-free fallback. Alternatives rejected: per-run unique entry files reassembled at read (loses the chain's ordering guarantee and multiplies `fsync`s); an in-process mutex only (does not cover `--approve-action` running concurrently with an execute, which is the realistic case); advisory `flock` (not uniformly available across the allowlisted filesystems and silently degrades). Consequences: a serialisation point on protected-action consumption, bounded at ~2 `fsync`s per append; the lockfile is one more file whose mode and filesystem are verified; stale-lock handling is itself security-relevant and is tested in both directions. Status: accepted.

### ADR-0036 (new) — Pilot tests run from a separate `playwright.pilot.config.js`, not a project in the shared config.
Context: `playwright.config.js` declares reporters (`json` → `reports/`, `allure-playwright`) and `outputDir` (`reports/test-artifacts/`) at the top level and excludes `**/regression/**` via top-level `testIgnore`, with `baseURL` defaulting to a third-party demo site. A project-level `use` override cannot disable a top-level reporter, cannot un-ignore its own tests and cannot stop allure from persisting failure attachments outside `PilotRoots`. Decision: 18F adds `playwright.pilot.config.js` (precedent: `playwright.demo.config.js`) with its own `testDir`, empty `testIgnore`, `list` + `json`-into-`run/` reporters, no allure, `baseURL: undefined`, all capture off, `retries: 0`, `workers: 1` and `outputDir: run/pilot-test-results/`; the `pilot` project is removed from the shared config; `npm run test:pilot` and the CI pilot job use only the new config; the artifact negative test scans `reports/`, `allure-results/`, `test-results/` **and** the real `outputDir`. Consequences: one more config file to keep in sync (a static check asserts no allure reporter and no `baseURL` string, and that the pilot suite is actually collected); pilot tests are invisible to a bare `npx playwright test`, which is intended. Status: accepted.

### ADR-0037 (new) — Runtime secret registration with explicit barriers; synchronous sinks carry codes only.
Context: L01's remaining gaps were values the application writes to `localStorage`/`sessionStorage` mid-run and tokens in JSON response bodies (never registered), plus a flush mismatch: the cookie/storage diff is async while `Logger`'s console channel is synchronous (its file append is queued and drained only by `Logger.flush()`), so a sink could emit before a registration landed. Decision: `registerRuntimeValue` plus bounded, key- and shape-driven extraction from JSON bodies and storage diffs at defined barriers (navigation commit, `load`, each `response` with `Set-Cookie`, after each `gate.perform`, before each async sink write, run end); every **asynchronous** sink awaits `boundary.settle()` first; every **synchronous** sink in pilot mode accepts only `{code, allow-listed fields}`, never free text — so the one channel that cannot wait is also the one channel that can never carry an unregistered value; `cleanupAll` ends with `settle()` then `Logger.flush()`. Shard merge unions worker registries through a blinded `secretIndex` (HMAC under an in-memory per-run key passed to workers via the spawn environment) and refuses bundles without a boundary attestation. Consequences: pilot log lines are less chatty by design and the operator guide must show the code table; a `settle()` timeout refuses the run; the blinded index leaves an undelimited-embedding residual covered by worker-local `assertClean` and the shard canary shape. Status: accepted.
