# Phase 18 architecture — revision 11 patch (ARCH-11)

Normative addendum to the [rev 10 patch](phase-18-rev10-patch.md). It closes SEC-10 (`docs/security/phase-18-design-review-9.md`) major **M-15** and minors **m-29..m-33**, specifies the **H-5** fallback, and removes the stale text SEC-10 lists. Base for compatibility claims is `2572e73`. No Must criterion, no OD-01..OD-19 and no recorded owner decision (OWNER-01..OWNER-11) is weakened; four controls are strengthened (the ledger/fixture distinction becomes unforgeable, approvals become immutable, the redirect fallback becomes a refusal instead of an emulation, and the AC-092 attack surface becomes bounded and therefore falsifiable). Nothing here authorises implementation, merge, tag or publication.

Status: DRAFT rev 11, pending SEC-11 on the rev 11 delta only. Two items (R-7, R-8) are flagged in 5h rather than silently resolved; R-7 is an owner decision point.

Runtime facts verified on Node 22.19.0 while writing this patch (re-verify on Node 24 in CI before implementation):
- `Object.getOwnPropertyDescriptor(net.Server.prototype, "listening").get` is a function (the prototype getter exists).
- `net.Server.prototype.address` is an own prototype method.
- An ergonomic brand check (`static is(x){ try { return #b in x } catch { return false } }`) returns `true` for a constructed instance and `false` for both `Object.create(C.prototype)` and `{}`.
- `falcon.js:474-540` parses only literal flags from `process.argv.slice(2)` and never consults an unknown flag; no argv value selects a module to load (this closes SEC-10's "UNVERIFIED in detail" note on rev 10 4a.4(b)).

What changes, in one line each:
1. **M-15: trust is inverted.** The gate never reads a `scope` string. A ledger approval is identified by an unforgeable private-field brand minted only inside `ApprovalStore`'s verified consumption path; everything else is fixture-class by definition and is held to the loopback-only rules.
2. **Approvals and bindings are immutable.** Deep-frozen at seal, with `scope` removed from the object entirely.
3. **Server identity is read through captured intrinsics**, so a duck-typed server cannot lie.
4. **`PilotRuntime` has a closed option allowlist**, so no source can be passed through `falcon.js`.
5. **AC-092's attack surface is bounded** (m-30) and extended with the five M-15 cases plus prototype pollution.
6. **The redirect fallback aborts or the capability is NO-GO** (H-5, m-32); one approved transmission per approval (m-31).
7. **m-29 and m-33 text corrections**, including the rev 9 3b.1 overclaim and the plan's mislabelled rows.

## 5a. M-15 — the ledger/fixture distinction is unforgeable (REPLACES rev 10 4a.2 item 3, 4a.3 items 6 and 8; AMENDS ADR-0041 and ADR-0044)

### 5a.1 The defect being removed

Rev 10 distinguished a ledger approval from a fixture approval by a self-declared, mutable `scope` string on a mutable object, and let a caller-supplied source return it. Four consequences, all reachable from the shipped public surface: relabelling `approval.scope = "ledger"`; replacing `approval.binding`; wrapping a real resolve in `{scope: "ledger", resolve}`; and presenting a duck-typed `server` whose own `address()` reports a loopback literal. The fix is not a longer check list on `scope`. **`scope` ceases to be a trust input and is deleted from approval objects.**

### 5a.2 The brand (18D, production code)

1. **Where it is minted.** `src/core/pilot/approval/ApprovalStore.js` declares a module-private class, **not exported under any name**:

   ```
   class LedgerApproval {
       #ledgerVerified;                 // installed only by this constructor
       constructor(sealedFields) { this.#ledgerVerified = true; /* assign, then deep-freeze */ }
       static isLedgerApproval(value) { try { return #ledgerVerified in value; } catch { return false; } }
   }
   ```

   The constructor is called from exactly **one** private call site: `ApprovalStore`'s `#sealVerified()`, invoked only after the full existing verification sequence has succeeded — hash-chain verification over the segmented audit log and anchors, eight-field binding equality, `falconBuild` identity, run-token claim, the local lock, and the exclusive `O_EXCL` consumption marker with file and parent `fsync`. **Branding and verification are the same code path and may not be split into separate exported functions.**
2. **What is exported.** `module.exports = { ApprovalStore, isLedgerApproval }` where `isLedgerApproval` is `LedgerApproval.isLedgerApproval` bound and frozen. It is a **predicate only**. There is **no** exported `brand()`, no exported `WeakSet`, no exported symbol, no `add`/`register`/`seal` surface, and no exported class whose constructor installs the field. A wrapper source that returns a ledger-looking plain object cannot acquire the field, because the only installer is a constructor no other module can name.
3. **Why not a symbol or a WeakSet.** A module-private `Symbol` is forgeable the moment any code can read it off a genuine approval (`Object.getOwnPropertySymbols`). A module-private `WeakSet` is sound only while no `add` surface is exported; an exported `brand(obj)` is a mint function and reopens M-15 (see flag 1 in the handoff). A private class field is unreadable, uncopyable and uninstallable from outside the class body, and `Object.create(LedgerApproval.prototype)` does **not** acquire it (verified above). This is the only one of the three that survives an attacker holding a genuine branded instance.
4. **No in-process ledger writer (the second half of the closure).** `ApprovalStore` exposes **no** method that creates, writes, appends, imports or re-seals a ledger entry — `consume`, `verify` and read accessors only. The ledger **writer** lives in `src/core/pilot/approval/ApprovalCliWriter.js`, which is required by **`falcon.js`'s `--approve-action` path and nothing else**, and whose exported `write()` refuses unless, in this order: `CI`/`GITHUB_ACTIONS` are unset (exit 1, `approve_flag_in_ci`); `require("node:tty").isatty(0) && require("node:tty").isatty(1)` — **the syscall, never `process.stdin.isTTY`, which is writable in-process** (exit 1, `approve_flag_non_interactive`); and a freshly generated random challenge phrase is read back from fd 0 with **no parameter, option, env key or file by which it can be supplied programmatically** (exit 1, `approve_challenge_failed`). Consequence: within an unmodified repository, no in-process caller can create a branded approval at all, including one at a temporary approvals root. **Residual, stated not accepted here:** a human who types the challenge at a real terminal, or an actor who allocates a pty in a child process, is an approver by definition — the same residual SEC-10 §4 already records for same-uid interactive approval, and `child_process` from a new test file is the OWNER-10 accepted class (5c).
5. **Immutability (SEC-10 M-15(c)).** `#sealVerified()` deep-freezes the approval before returning it: the instance, `binding`, the lease `{method, origin, path}` triple, and every nested object and array are `Object.freeze`d; no field is an accessor; the `server` slot does not exist on a ledger approval. `Object.isFrozen` is asserted on the instance and on each nested object at seal, and a failure is `PILOT_INTERNAL_ERROR` exit 18, reason `approval_not_sealed`. A frozen object cannot be relabelled, re-bound, re-defined with `Object.defineProperty` or extended, and `Object.prototype` pollution cannot introduce an **own** property onto it.
6. **`scope` is deleted.** No approval object carries a `scope` field. Any object that does is, by that fact alone, not a ledger approval (it cannot be: ledger approvals are frozen instances without the field), and the field is never read as a trust input anywhere in `src/`. The term survives only in withdrawal text.

### 5a.3 Exact checks in `gate.perform` (REPLACES rev 10 4a.3 item 8)

`PilotActionGate.perform(ctx, {handle, action, value, source})` — the signature at `authenticated-pilots.md:97` is unchanged; `ctx.approvalArm` carries the resolved approval. Before any arming and before any dispatch, in this order, each failure refusing with the stated code and **zero** requests:

1. `approval == null` → `APPROVAL_REQUIRED` exit 14.
2. `isLedgerApproval(approval) === true` → **ledger class**. Proceed to the unchanged eight-field binding equality, lease triple, run token, identity re-verification and classification maximum of rev 9 3a.3. **No loopback restriction applies**; this is the production path a human approved. Nothing else grants ledger class — not a `scope` value, not `instanceof`, not a constructor name, not a duck-typed predicate on the object.
3. Otherwise → **fixture class, unconditionally**, whatever the object declares. Then **all** of the following must hold:
   (a) `Object.isFrozen(approval)` and `Object.isFrozen(approval.binding)` and every nested object frozen; otherwise `APPROVAL_REQUIRED` exit 14, reason `fixture_approval_mutable`.
   (b) A `server` reference is present in a non-enumerable slot and `ServerCtor` — `require("node:net").Server` captured at module load, before any test code runs — satisfies `approval.server instanceof ServerCtor`; otherwise exit 14, reason `fixture_approval_server_untrusted`. A duck-typed `{listening: true, address: () => …}` fails here.
   (c) The address is read as `ServerAddress.call(approval.server)` where `ServerAddress = net.Server.prototype.address` is captured at module load; the object's own `address` property, if any, is **never** called. The result must be a non-null object with `family === "IPv4" && address === "127.0.0.1"` or `family === "IPv6" && address === "::1"`, and an integer `port` in 1..65535; otherwise exit 14, reason `fixture_approval_non_loopback`.
   (d) Liveness is read as `ListeningGetter.call(approval.server)` where `ListeningGetter = Object.getOwnPropertyDescriptor(net.Server.prototype, "listening").get` is captured at module load, and must be `true`. If the descriptor or its getter is absent on the running Node version, the gate **fails closed** at module load (`PILOT_INTERNAL_ERROR` exit 18, reason `net_intrinsic_unavailable`) and never falls back to a plain `.listening` read.
   (e) The **live destination** origin for this action equals `http://127.0.0.1:<port>` or `http://[::1]:<port>` built from (c) as a literal, including the port; the live manifest digest equals `binding.manifestDigest`; and every route origin of the freshly resolved manifest is that same derived origin. Otherwise exit 14, reason `fixture_approval_non_loopback`.
   (f) The capability check of rev 10 4a.3(3) is performed **by the authority at resolve time** and, at consume time, the gate additionally requires the approval's non-enumerable `capabilityProof` slot to be a 32-byte `Buffer` compared with `crypto.timingSafeEqual` against the value derived from the live server object in the authority's own slot — a check that fails for any serialised, cloned or hand-built object. Otherwise exit 14, reason `fixture_approval_not_live`.
   (g) The eight-field binding equality, lease triple, identity re-verification and classification maximum then apply exactly as in case 2; the fixture class **adds** constraints and removes none.
4. Any throw inside steps 1–3 → `PILOT_INTERNAL_ERROR` exit 18. No step may be skipped on the basis of a value read from the approval.

### 5a.4 `PilotRuntime` and the harness seam (REPLACES rev 10 4a.2 item 3)

1. **Class identity, not a string.** `PilotRuntime` accepts a resolver only if every source in it is **the frozen singleton instance** the runtime itself constructed (`source === this.#ledgerSource`, reference equality) and the source list length is exactly 1. A source that merely declares `scope: "ledger"` is refused: `PILOT_INTERNAL_ERROR` exit 18, reason `non_ledger_source_in_production_runtime`. The `scope !== "ledger"` test of rev 10 4a.2 is **deleted**.
2. **Closed option allowlist.** `PilotRuntime`'s options object is validated against a frozen key allowlist that contains **no** `sources`, `resolver`, `approvalAuthority`, `gate` or `store` key; any unknown key is `PILOT_INTERNAL_ERROR` exit 18, reason `unknown_runtime_option`. There is therefore **nothing to pass through `falcon.js`**, which in any case parses only literal flags (verified above).
3. **No injection API in production.** There is no `__forTests`, no one-shot setter, no registry and no token. The harness obtains the fixture path by constructing `PilotApprovalResolver` and `PilotActionGate` **directly**, which is test code calling test-visible constructors; `PilotRuntime` is never involved. This is strictly less surface than a one-shot injection and satisfies the same requirement.
4. **Harness-side server identity (closes the duck-typed and second-port cases at source).** `tests/pilot/fixtures/PilotFixtureServer.cjs` holds a module-private `WeakSet` populated **only** inside `start()` and exports **only** the predicate `isFixtureServer(server)`; no `add`/`register` surface exists. `FixtureApprovalAuthority`'s constructor requires `isFixtureServer(server) === true` in addition to the production-side checks of 5a.3, so a real `net.Server` the test created itself — including one that forwards — is refused by the shipped harness (see R-8).

## 5b. m-29 — three corrections (18D/18E)

1. **(a) Test ledger root.** The in-process check of rev 10 4a.4(a) constructs its `ledgerSource` with `new ApprovalStore({ approvalsRoot: <a fresh directory under os.tmpdir()>, … })` — created by the test, outside the repository and outside `run/`, removed in teardown, passed as a constructor argument, **never** through an environment variable or flag. The `run/approvals`-absent and `run/`-digest-unchanged assertions are then evaluated against the real roots, which the test never opens. That store can only *consume*; it has no writer (5a.2 item 4), so it resolves `null`.
2. **(b) Restate the fs claim.** Rev 10 line 10's "no filesystem dependency at all" is **replaced** by: *the approval half's require graph is filesystem-free — `FixtureApprovalAuthority.cjs` and `PilotFixtureServer.cjs` require no `fs`, `fs/promises`, `SafeFs`, `ApprovalStore`, `AuditLog` or `RunToken` — while the tests-only executable itself necessarily reaches production pilot modules and reads in-repo fixture, manifest and plan files through the privileged `SafeFs` loader.* No document may state or imply that the executable performs no filesystem access.
3. **(c) "Missing" versus "unverifiable", defined exactly.** On the **resolved real path** of the approvals root:
   - **Missing** = the root does not exist (`ENOENT`), or exists and contains no ledger object at all. → `APPROVAL_REQUIRED` **exit 14**. Trust is restored from nothing (rev 10 4c item 5 unchanged).
   - **Unverifiable** = the root exists and anything is present but cannot be fully verified: a zero-length ledger or segment file, a missing or zero-length `anchors.log`, a truncated final record, a segment without a header, an unparseable header, a foreign `falconBuild`, a broken hash chain, a missing segment referenced by an anchor, a permission or `EACCES` failure, or any read error other than `ENOENT` on the root itself. → `PILOT_INTERNAL_ERROR` **exit 18**, reason `approval_history_unverifiable`. Never downgraded to exit 14.
   - **Genesis entry.** A freshly initialised ledger writes a first audit entry recording that no prior history was found, with the run id, `falconBuild`, the resolved root real path and the observed filesystem id. The entry is part of the chain, so a later reset is visible in audit. A root that is missing stays missing until an interactive approve path initialises it; nothing initialises it to satisfy a read.

## 5c. m-30 — the AC-092 attack surface is bounded and therefore falsifiable (18D/18F)

**In scope** for AC-092 and `neg-fixture-no-arbitrary-target`, driven from the shipped harness with repository source unmodified: every argument value accepted by the public surface; own-property assignment, deletion and `Object.defineProperty` on any object the surface returns; `Object.prototype` (and `Array.prototype`, `Function.prototype`) pollution of the keys the design reads — `scope`, `binding`, `server`, `listening`, `address`, `family`, `port`, `capabilityProof`, `manifestDigest`; duck-typed substitutes for the server, the approval, the source and the resolver; wrapper and shadowing sources; serialisation, structured clone and cross-process replay; the proxy and forwarding paths of SEC-09 m-25(b)/(c); literal `require` of any production module under `src/core/pilot/` and a call to every exported function with adversarial arguments.

**Out of scope, as repository modification under OWNER-10, and the AC-092 wording must say so:** monkeypatching built-ins or intrinsics (`net.Server`, `Object.freeze`, `crypto.timingSafeEqual`); `require.cache` manipulation; `Module._load`, `Module.prototype.require`, `createRequire` or any non-literal `require`/`import()`; `process.binding`; `child_process` or `node:worker_threads` spawned from a new or edited test file; a pty allocation; editing the fixture authority, the fixture server, the harness or any production file; and adding a new test file that implements a forwarding or proxying server (R-8). These are the OWNER-10 accepted class; the controls are code review, protected branches and repository write governance, which Falcon does not verify.

**Require-graph walker (ties m-24(e)).** The walker resolves `require(path.join(<string literals>))` — the form `scripts/*.js` uses today — and `require("<literal>")`, and **fails closed** (`UNRESOLVABLE_REQUIRE`, naming file and line) on every other non-literal `require` outside `tests/`. It must not silently skip a call it cannot resolve.

## 5d. m-31, m-32, H-5 — one transmission, and a fallback that refuses (18B/18C/DOC; AMENDS ADR-0042 and rev 10 4d.2)

1. **m-31: at most one transmission of the approved non-GET per approval.** A counter `transmissions` lives in the consumed lease, starts at 0, and is incremented when a request carrying the approved method and body is **observed leaving**. Rule 3 of rev 10 4d.2 is amended: a continuation hop that preserves a non-GET method is permitted only while `transmissions === 0`; once it is 1, any further non-GET hop — **including one to the identical target** — is aborted `POLICY_ROUTE_DENIED`, reason `redirect_would_retransmit_approved_body`. Every transmission is recorded in the audit entry for the attempt with hop index, method, origin and canonical path. A self-redirect loop therefore yields exactly one mutation, not up to `MAX_REDIRECTS`.
   - `neg-n2-arming` case **(k)** is extended: a fixture endpoint that 307s to itself asserts the server-side mutation count is **≤ 1** and that the abort code is `redirect_would_retransmit_approved_body`. Inversion: remove the counter and the mutation count rises.
2. **H-5 / m-32(a): SPIKE-R must prove an enforcement point, not only an observation point.** For each of 301, 302, 303, 307 and 308, SPIKE-R records (i) whether the route handler is invoked for the hop, (ii) the method and body actually carried, and (iii) **whether Falcon can prevent the hop from being sent** (abort, or refuse before dispatch). The outcome selects one of two branches, both specified now so nothing is chosen at implementation time:
   - **Branch A — an enforcement point exists for every hop.** Rules 1–8 of rev 10 4d.2 ship as written, plus the transmission counter of item 1.
   - **Branch B — no enforcement point exists for one or more hop classes.** Then **protected non-GET actions are NO-GO for Phase 18**: the gate refuses to arm any approved non-GET (`POLICY_REDIRECT_UNOBSERVABLE`, exit 18, naming the unenforceable hop classes), zero approved mutations are dispatched, and the capability is documented as not shipped. Falcon does **not** emulate the chain with `route.fetch({maxRedirects: 0})`, does not "abort" a hop it cannot intercept, and does not claim a one-transmission guarantee it cannot enforce. See R-7: this removes the headline protected-action capability and is an owner decision point.
   - The mandated-fallback sentences at `authenticated-pilots.md:260` and the SPIKE-R row at `authenticated-pilots.md:645` are **corrected**: `route.fetch({maxRedirects: 0})` is **withdrawn as the shipped implementation** and is retained only as a SPIKE-R measurement technique. `neg-n01-network`'s 302 case asserts the observed behaviour of the selected branch, not the emulation.
3. **m-32(c): case (q) restated.** The chain deadline is `min(windowMs + 5000, 30000)` ms measured from the first matching request. Because `windowMs ≤ 10000`, the 30000 ms term is a **defensive upper bound that is unreachable with any valid configuration**; it is documented as such and is **not** tested. Case **(q)** becomes: with an injected monotonic clock, a chain that exceeds `windowMs + 5000` aborts with `POLICY_REDIRECT_DEADLINE`, asserted at `windowMs` = 250, 2000 and 10000. The unbuildable 30000 ms half is **deleted**. Inversion: remove the deadline and the case must fail.
