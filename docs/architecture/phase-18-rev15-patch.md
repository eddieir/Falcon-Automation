## 9a. M-18 — the origin gate keys on the request's initiator, its whole ancestor chain, and the top-level document (REPLACES rev 14 8a.1, 8a.2 and 8a.3 rows 1 to 4; AMENDS AC-086 and AC-096; NEW AC-097)

> **Superseded and deferred by owner decision OWNER-12 (Option C):** no protected non-GET request reaches this mechanism in Phase 18; the text below is preserved unchanged as an input to the deferred item 18P-PROTECTED-NONGET and is not a Phase 18 requirement. See rev 16 sections 10a and 10b.

SEC-14's finding is adopted in full and without qualification: **rev 14 8a.1's claims (1), (2), (4) and (5), the 8a.2 restatement, and the "No" verdicts on 8a.3 rows 1, 2 and 4 are false for a request initiated by a cross-origin frame** (U3). CORS and SameSite are computed from the initiator's origin and its ancestor chain, not from the top-level document's origin. Rev 14's gate was therefore a partial control written as an absolute. The architect defect is recorded in traceability (9f D, item 31) and the overstated sentences are WITHDRAWN at their sites under the m-25 prohibited-phrase mechanism, not softened.

### 9a.1 The rule, restated (normative; REPLACES rev 14 8a.1 in its entirety)

1. **Definitions.** At arming time, for a protected action:
   - `pageOrigin` = the serialized origin of the page's **top-level** document, computed **from Playwright** as `page.mainFrame().url()` parsed by the WHATWG `URL` parser. It is **never** obtained from page-evaluated script (no `page.evaluate`, no `location.origin`, no injected helper), because the document under test is in the threat model.
   - `initiatorOrigin` = the serialized origin of the frame that initiated the request, computed from `request.frame().url()` by the same parser.
   - `approvedOrigin` = the origin recorded in the consumed ledger approval.
   - `targetOrigin` = the serialized origin of the request URL that will be issued at hop 0.
2. **Parsing, scheme first (SEC-14 nit).** For every URL above, the parser result is screened in this order, and the first failure is a refusal:
   1. `url.protocol` must be exactly `http:` or `https:`. This check comes **before** any read of `.origin`, because `blob:http://a.test/x` yields `.origin` `http://a.test` rather than `null` (U7); a scheme-last implementation would admit a `blob:` initiator as same-origin.
   2. `url.username` and `url.password` must both be empty — userinfo is dropped from `.origin` (U7) and so cannot be detected there.
   3. `url.hostname` must not end in `.` — a trailing dot is preserved in `.origin` (U7) and must be refused rather than normalised away.
   4. Only then is `url.origin` read, compared as the serialized origin (scheme, host, port) with the default port omitted, ASCII-lowercased, by `===` on the resulting strings. No host-suffix, no eTLD+1, no "same-site" relaxation: **origin equality, not site equality.**
3. **Gate, before arming.** Falcon arms a route for a protected request **only if all four origins are equal**:

   `initiatorOrigin === pageOrigin === approvedOrigin === targetOrigin`

   **and** every ancestor frame of the initiator is same-origin with `pageOrigin` as well. The normative form of the ancestor requirement, chosen because it is the simplest sufficient one SEC-14 named, is:

   > `request.frame() === page.mainFrame()` — reference identity against the page's main frame.

   A request that satisfies reference identity is by construction initiated by the top-level document, has an empty ancestor chain, and cannot be a nested or sibling-frame initiator. An ancestor walk via `parentFrame()` is **not** required and is **not** specified as an alternative; a nested same-origin A>A>A chain is refused along with A>B>A, which is a deliberate over-refusal in the safe direction and is disclosed as such in the limitation text (9a.2) and in 9a.3 row 10.
4. **`Origin` header cross-check.** Where the routed request carries an `Origin` request header, its value must parse (rule 2) and equal `pageOrigin`. A present-but-unequal `Origin`, or one that fails rule 2, is a refusal even if rule 3 passed. A **missing** `Origin` is not by itself a refusal (same-origin GET-like requests legitimately omit it), and no security property is claimed from its absence; the header is a cross-check on Falcon's own frame accounting, not a source of truth.
5. **Fail closed, with no exception, when the initiator cannot be established.** Each of the following is a refusal **before arming**, with reason `POLICY_PROTECTED_INITIATOR_UNSUPPORTED`, **exit 18**:
   - `request.serviceWorker()` is non-null (Chromium), or `request.frame()` throws, returns a falsy value, returns a detached frame, or returns a frame whose `url()` is empty, `about:blank`, or fails rule 2 — the worker and service-worker cases SEC-14 named;
   - the request is initiated by a popup, an opener, or any page other than the page under test (reference identity against **this** page's `mainFrame()` already excludes these, and the refusal is stated explicitly so the exclusion is not read as incidental);
   - the engine is one where `request.serviceWorker()` is always `null` (Firefox, WebKit, 9.0 item 2) **and** worker-initiated protected requests are therefore indistinguishable from frame-initiated ones by that signal alone. On those engines the reference-identity check of rule 3 is the only discriminator, and `serviceWorkers: 'block'` remains mandatory under every option that arms routed protected requests (rev 14 8a.4). This limitation is disclosed, not closed.

   No `POLICY_PROTECTED_INITIATOR_UNSUPPORTED` path is recoverable, retried, or downgraded to a warning. The step fails, the run fails, the page is torn down.
6. **Scope: every routed protected request.** Unchanged from rev 14 8a.1(3) and for the same reason (U1: plain `route.continue()` already suppresses the preflight). The initiator requirement is part of the same gate, under every R-7 option that arms routed protected requests, independent of the mechanism that performs the request.
7. **The absolute claim, restated correctly (REPLACES rev 14 8a.1(4)).** Under every option that remains available, Falcon never routes, performs, continues, fulfils or emulates a protected request **unless that request was initiated by the page's own top-level document and its target origin equals that document's origin and the approved origin**. A manifest that declares a cross-origin protected route is still a manifest error refused at load (`POLICY_PROTECTED_CROSS_ORIGIN_UNSUPPORTED`, exit 18). Rev 14's sentence "no cross-origin routed protected request exists in Phase 18" is **retained only as a statement about the target origin** and is annotated at its sites to say that it never covered the initiator; the initiator case is covered by this rule, not by that sentence.
8. **Hop-0 re-check: the same rule, not a weaker one.** Immediately before performing the hop-0 request inside the route handler, **all** of rules 2 to 5 are re-evaluated — the four-origin equality, the reference-identity initiator check, and the `Origin` cross-check — because the top-level document can navigate and frames can be created or detached between arming and dispatch. A mismatch aborts the route and fails the run: `POLICY_PROTECTED_ORIGIN_CHANGED` (exit 18) for an origin change, `POLICY_PROTECTED_INITIATOR_UNSUPPORTED` (exit 18) for an initiator that can no longer be established. **This remains labelled detection, not prevention**, because whether `route.abort()` prevents transmission of hop 0 itself is UNVERIFIED on a single run (U4); 9d row 2 adds the repetition SEC-14 asked for before any prevention claim is made. No prevention claim rests on the re-check.
9. **Cross-origin `Location` is never followed and never performed.** Unchanged from rev 14 8a.1(6).

### 9a.2 Rewritten 6j.1(7) narrowing (REPLACES rev 14 8a.2, which SEC-14 did not accept as written)

> **6j.1(7), rev 15 restatement.** `route.fetch({maxRedirects: 0})` remains **withdrawn** as a means of reconstructing, replaying, emulating or continuing a redirect chain, and its result remains **never** evidence about browser-followed redirect behaviour. It is permitted **solely** as the performer of the single approved hop-0 request of a protected action that is **same-origin in the full sense defined in section 9a.1**, namely: the request's **initiator frame is the page's own main frame** (so the initiator's origin and its — empty — ancestor chain are trivially the top-level origin), **and** the initiator origin, the page's top-level origin, the approved origin and the hop-0 target origin are **all four equal** as serialized origins, **and** any `Origin` request header present equals that origin. Its response is either passed through unchanged (non-3xx) or discarded entirely (3xx), and no subsequent hop is performed. For any protected request that is not same-origin in that sense — including a request initiated by a nested or cross-origin frame, by a worker or service worker, by a popup or an opener, or one whose initiator cannot be established — `route.fetch` is **withdrawn without exception** and the request is refused before arming.
>
> The limitation text must state that even in the permitted case: the request carries **no `Sec-Fetch-*` headers** (this is a property of `route.fetch`, not of routing in general — under `route.continue()` the browser's `Sec-Fetch-*` headers are **preserved**, U1); **a discarded 3xx is what the page observes as 204**, while a non-3xx hop-0 response is passed through with its own status, so the page sees 200 where the application returned 200 (U2); a `Set-Cookie` on a discarded 3xx is not applied to the context; and **a protected action triggered from any frame other than the top-level document is unavailable**, including a same-origin nested frame.

## 9b. m-49 — the 8c.1(1) call form (REPLACES rev 14 8c.1 item 1)

SEC-14 U6 is adopted: `uncurry(Object.getPrototypeOf)(server)` throws `TypeError`, because `uncurry` supplies the server as `this` and no argument, so the assertion would fail for a **genuine** server — a fail-closed-but-useless check that would have broken the fixture path outright.

1. **Corrected form.** Assertion 8c.1(1) becomes: `CAPTURED_GET_PROTOTYPE_OF(server) === CAPTURED_HTTP_SERVER_PROTOTYPE`, where `CAPTURED_GET_PROTOTYPE_OF` is a direct reference to `Object.getPrototypeOf` (equivalently `Reflect.getPrototypeOf`) captured at fixture-module load **before** the module requires anything else, and **called directly, not uncurried**. `uncurry` remains correct for prototype *methods* (`EventEmitter.prototype.emit`, `eventNames`, `listenerCount`, `Function.prototype.toString`) and is wrong for *static* functions; rev 15 states that distinction normatively so the error class cannot recur: **uncurry a method, call a static directly.**
2. **Verification.** F18's existing inversion is kept, and the **F18 control** is made explicit and mandatory: a genuine, untampered fixture server must **pass** every assertion in 8c.1, including (1). *Inversion of the control:* restore the rev 14 call form and the F18 control must fail with `TypeError` surfaced as `PILOT_INTERNAL_ERROR` exit 18 rather than as `fixture_server_repurposed` exit 14 — the two outcomes must stay distinguishable, because a crashing check is a defect and not a detection.
3. A **static sweep** is added to the same case list: every captured primitive is recorded in the design with its call form (method or static), and the control asserts each capture is invoked in its recorded form. This is a smoke check for the m-49 error class, carries **no** integrity claim, and does not revive the claim rev 14 8b deleted.

## 9c. m-50 — listener identity and the prototype-method route (AMENDS rev 14 8c.1, 8c.2, 8c.3 and 8c.4; AMENDS AC-092)

SEC-14's X1 (replace Node's `connection` listener with a wrapper, count unchanged) and X2 (post-load patch of `http.ServerResponse.prototype.end`) both pass every rev 14 check and serve attacker content. Both are post-load routes. Rev 14 8c.2's snapshot counted listeners without identifying them; that is corrected here.

### 9c.1 Listener identity, recorded by reference (closes X1)

1. At the `listening` event the record stores, for every event name in `eventNames(server)`, the **ordered array of listener function references** as well as the count, read through uncurried captured `EventEmitter.prototype.eventNames`, `listenerCount` and `listeners` (and `rawListeners`, so a `once`-wrapped listener is compared in its raw form rather than through the wrapper).
2. At authority construction and at consume, the live snapshot must be **exactly equal**: the same name set, the same counts, and **element-wise reference identity** of the raw listener arrays in order. Any inequality is `APPROVAL_REQUIRED` **exit 14**, reason `fixture_server_repurposed`.
3. Ordering is part of the comparison, so `prependListener` with the genuine function is also detected. The fixture module's own listener registration must therefore be deterministic and complete **before** the `listening` event; this is restated as a normative constraint on the fixture module, alongside the rev 14 `setTimeout` ordering constraint.
4. Holding listener references in the record keeps those functions reachable for the life of the authority. That is a bounded, intentional retention of a handful of function references for the lifetime of a short-lived fixture server, and it is stated rather than ignored; it is not a leak concern at fixture scale and no weak-reference scheme is specified.
5. **Verification — F24.** After the `listening` event, remove Node's own `connection` listener and add a behaviour-preserving wrapper, leaving the count unchanged. Expected: exit 14 `fixture_server_repurposed`. *Inversion:* compare counts only, as rev 14 did, and F24 must **fail** (it is SEC-14's X1, which served attacker content undetected). A second variant covers `prependListener` with the genuine function reference, where only ordering changes.

### 9c.2 The `ServerResponse` / `IncomingMessage` prototype-method route (X2)

SEC-14 allowed either closure. Rev 15 takes the **assertion** half for the methods that carry the response body, and records the remainder under R-8 — both, rather than one, because the assertion is cheap and the residual is unavoidable:

1. **Captured and compared.** At fixture-module load the design captures, by reference, the following prototype methods and compares them at construction and at consume for reference identity with the live values: on `http.ServerResponse.prototype` — `end`, `write`, `writeHead`, `setHeader`, `getHeader`, `removeHeader`, `flushHeaders`; on `http.IncomingMessage.prototype` — `on`, `setEncoding`, `destroy`. Each comparison also asserts the property is an **own data property** of the prototype with the captured value (via a captured `Object.getOwnPropertyDescriptor`), so an accessor planted on the prototype cannot satisfy the equality check indirectly.
2. **Stated residual under R-8 (new 8c.3 item 6).** This list is **enumerated, not exhaustive**: a post-load patch of any other method or accessor on those prototypes, on `http.OutgoingMessage.prototype`, on `net.Socket.prototype`, or on `stream.Writable.prototype`, is **not** detected. The rev 14 7c.4 coverage sentence is corrected **again** to say exactly that, and the correction names the enumerated-not-exhaustive character of the list so the sentence cannot be read as full prototype coverage. Rev 14's statement that the four assertions close "the four routes" is annotated: they closed the four routes **SEC-13** demonstrated, and SEC-14 demonstrated two more.
3. **Verification — F25.** Post-load patch of `http.ServerResponse.prototype.end` with a behaviour-preserving forwarder that also writes attacker content. Expected: exit 14 `fixture_server_repurposed`. *Inversion:* drop the prototype-method capture set and F25 must **fail** (SEC-14's X2). A **second, documented-limitation variant (F25b)**, following the F23/L20 pattern, patches a method **outside** the enumerated set (for example on `http.OutgoingMessage.prototype`, or `net.Socket.prototype.write`) and asserts the server **is accepted**, encoding the R-8 boundary in the suite so it cannot silently drift. If F25b ever reports a refusal, 8c.3 item 6 is stale and must be rewritten.
4. **X3 and X4 are recorded, not claimed closed.** SEC-14's `_handle.onconnection` wrap (X3) and `listening`-listener swap (X4) pass every rev 14 check. X4 is now closed by 9c.1 (the `listening` listener is in the recorded reference array). **X3 is not closed**: wrapping `_handle.onconnection` preserves the `_handle` owner linkage that rev 14 8c.1(3) checks and touches no listener array. It is added to 8c.3 as **item 7**, a stated residual under R-8, adjacent to existing item 4 (socket-level interception) and item 5 (a compatible substituted `_handle`). It is not accepted.

### 9c.3 F19 — `emit` must be a data property (SEC-14 nit)

F19's assertion set gains: using a **captured** `Object.getOwnPropertyDescriptor`, `EventEmitter.prototype.emit` must be an **own data property** of `EventEmitter.prototype` whose `value` is reference-identical to the capture — not an accessor. An accessor whose getter returns the captured function would otherwise satisfy the rev 14 equality comparison while interposing arbitrary code on every read. *Inversion:* plant such an accessor and the descriptor check must fail while the plain equality check passes. The same descriptor discipline applies to every prototype-method comparison introduced in 9c.2 item 1.

## 9e. R-7 — the three options re-presented with M-18 applied, and **NOT chosen**

> **Superseded and deferred by owner decision OWNER-12 (Option C):** no protected non-GET request reaches this mechanism in Phase 18; the text below is preserved unchanged as an input to the deferred item 18P-PROTECTED-NONGET and is not a Phase 18 requirement. See rev 16 sections 10a and 10b.

**Option A" — protected non-GET for subresource `fetch`/`XHR` only, via M1, same-origin only, main-frame-initiated only.**
- *Scope:* as rev 14 A', plus the full gate of 9a.1: four-origin equality, `request.frame() === page.mainFrame()`, the `Origin` cross-check, fail-closed on an unestablishable initiator, and the same rule re-evaluated at the hop-0 re-check.
