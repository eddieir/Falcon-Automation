# Claude Pro efficiency design

- Default: one coordinator, zero subagents until needed, at most two concurrent specialists, no nested spawning, at most one retry per task, no background research, no always-on executives, no automatic model escalation. The 27-role catalog does not raise any ceiling.
- Models: existing assignments are preserved. New roles use the lowest suitable model from the IDs already in the `CLAUDE.md` table: Haiku for narrow analysis (UX, data, privacy, customer validation, marketing), Sonnet for design and engineering analysis, Sonnet 5.5 only for the Chief Architect. Opus stays reserved for the Security Engineer. Fable is prohibited. New agents are read-only (no Edit/Write; most also lack Bash) and capped at 8 turns.
- Effective model: verify from runtime metadata at each role's first real dispatch and record it in the ledger. For PR #120 all 27 roles were checked on 2026-10-27 by running `claude -p --agent <name> --output-format json` in the worktree and comparing the `modelUsage` model with the agent's `model:` field: 27 of 27 match (QA `claude-sonnet-4-5` and Code Reviewer `claude-sonnet-4-6` in the activation tests, the other 25 in a minimal "reply OK" run). Self-reported model names were not used. Re-run this check after any model or Claude Code change. A mismatch or an unverifiable model blocks acceptance of that agent's output.
- Skills are lazy; the `skills:` agent field (full preload) is not used.
- Context: pass task/result packets with evidence paths ([AGENT-ROUTING](AGENT-ROUTING.md)); do not re-verify evidence another role already produced for the same revision.
- Budget exhaustion: write a checkpoint (`npm run production:checkpoint`), mark pending gates pending, never change routes silently or waive review, resume from the checkpoint.
- Measured overhead (headless trivial subagent sessions, 22 runs, same day): 9,363 to 27,824 input tokens per session and about USD 1.22 API-equivalent in total, mostly the session baseline (system prompt, tool schemas and the CTO's user-level plugin skill and MCP listings), so it varies by agent and is dominated by environment, not by Falcon's skills. It is not a Claude Pro quota figure. In one confounded comparison a Code Reviewer session read 11.4k input tokens before it had the `Skill` tool and 16.5k after, so listing skills costs roughly their descriptions; the four installed Falcon skill bodies and the three external ones load only when invoked. No saving percentage is claimed.
- Only six roles hold the `Skill` tool (Developer, QA, Code Reviewer, Security, Developer Experience, Performance & Reliability); other roles get skill guidance from the coordinator, so installing more skills does not raise their baseline.
