# Phase 18 residual-risk record T1 - gate-construction interface exposed by an authorised first-party change

**Status: OPEN - NOT ACCEPTED.** No owner acceptance, downgrade or closure has been given. This record states the risk; it does not decide it. Severity below is a proposed rationale for the owner, not a rating Security has assigned.

Sources: `phase-18-rev42-patch.md` (row T1, section 8), `phase-18-rev43-patch.md` (section 1, limits L1 to L8), `phase-18-design-review-36.md`, `-37.md`, `-38.md` (SEC-37 to SEC-39). Security's later finding m-143 adds five more miss routes, recorded in `phase-18-implementation-readiness.md` section 6 as limit L9.

| Field | Content |
|---|---|
| **Threat** | A change to shipped Falcon code makes the private gate-construction function (`createGate`) reachable from code outside the gate module, so another module can build a gate that the refusal logic did not create. |
| **Affected assets** | The FW-2 refusal (`worker_websocket_containment_unverified`, exit 18) and the gate identity it relies on; any acceptance criterion that assumes no outside module can construct or replace the gate. The mapping to individual Phase 18 acceptance criteria (for example the non-reachability criteria P18-AC-093 and P18-AC-098) is **not verified in this package**. |
| **Prerequisites** | A change that is **authorised**: it is reviewed and merged by the repository's normal process, and its file hash is in the trusted manifest, so C2 passes it. The author is first-party (Scope A). |
| **Exploit conditions** | The change exposes the function by a route that C1, as specified, does not observe. Known routes (Rev 43 L1 to L8 plus m-143): a static or prototype member of an exported class or function; a Proxy as the prototype of an exported value; pollution of built-in prototypes other than `Object`, `Function` and `Array`; replacement of an existing member of a baseline prototype; an export added after the load snapshot; behaviour that depends on the working directory, time, argv or call count; a property on `process`; statics on built-in constructors; writes onto another module's exports; a `require.cache` entry; a `process.on` listener that returns the function. |
| **Existing controls** | Code review (the only control for an authorised change). C1 (specified, unbuilt) for the DETECT-class routes. C2 (specified, unbuilt, independence unmet) for unauthorised change. The advisory scanner (diagnostic only; a CLEAN result proves nothing). C4 refusal remains in force while the FW-2 state is `unmeasured`. |
| **Evidence** | SEC-37: 11 export forms plus Proxy, `Object.prototype` and TypeScript forms returned CLEAN from the scanner. SEC-38: 7 of 8 evasions passed an approximation of the C1 design on Node 22, macOS. SEC-39: five more routes passed the same approximation. All reviewer runs are on Node 22 / macOS arm64; Node 24 and Linux are unchecked. Probe files are in the reviewers' scratchpads and are not committed. |
| **Severity rationale (proposed, not assigned)** | Impact is high for the gate's integrity if it occurs, because the refusal could be bypassed from inside. Likelihood under Scope A is low to moderate: it needs a deliberate or careless change that survives review. It is unresolved because no automated control would catch it. Security has not assigned a severity. |
| **Limitations** | C1 is observational and can never prove absence. The reviewers' evidence uses an approximation of C1, not a built C1. The list of routes is not claimed complete. No enumeration of further routes is planned (owner direction). |
| **Mitigation options** | (a) Accept as a review-carried residual under Scope A (owner decision; **not taken**). (b) Add C1 extensions for specific routes (owner decision; unmeasured; never a barrier). (c) Reduce the chance by structure: a small, frozen, hash-pinned gate module and a manifest entry that makes any edit to it need two-person review (needs IND-2, which is unmet). (d) Scope B isolation for untrusted code, which does not address a first-party change. |
| **Affected gates** | MG-8 (not cleared), MG-13 (implementation not done; acceptance contract awaiting Security acceptance), m-134 (OPEN). Also the Scope A trust boundary in `phase-18-rev42-patch.md` section 1. |
